01 / THE IDEA

What is QRecall?

“View once” can hide a button. It cannot prove a copy is gone.

THE PROBLEM

Seeing once isn’t deleting

A recipient can copy a message before it disappears. A conventional app has no reliable way to prove the remaining copy was destroyed.

THE APPROACH

Make the attempt observable

QRecall simulates a protocol where choosing to read changes the quantum information. A later verification can reveal interference with a recall attempt.

THE OUTCOME
✓

Proof, not a promise

The demo shows how a sender can test a receiver’s deletion claim before releasing the key that unlocks the encrypted message.

✳ QRecall is an educational simulation, not a production quantum-secure messaging system.

03 / THE FLOW

How it works.

Five steps, one simulated quantum channel, and a clear choice between recall and unlock.

  1. 01

    Send

    Alice encrypts the message and sends Bob a locked quantum register.

    MESSAGE
  2. 02

    Quantum key exchange SIMULATED

    Random bits and bases form the simulated quantum information behind the key.

    PREPARE
  3. 03

    Recall

    Bob measures in the recall basis and returns results as evidence of deletion.

    MEASURE
  4. 04

    Verification

    Alice checks the proof for mismatches that may reveal an attempt to keep information.

    CHECK
  5. 05

    Unlock

    If Alice chooses to release the key instead, Bob can recover and read the message.

    RELEASE
